# M24: paper support for the gold sleeve (draft, not deployed)

Engineering only, no new research question (2026-09-30, Claude). M19 adopted a 20% GOLDBEES sleeve as the research
reference (`momentum/m19_gold20_invvol_b2`, Calmar 0.712) and M20 checked it against higher costs, a bootstrap and
capacity. Paper code refused `portfolio.fixed_weights`; this removes that refusal so the book could be paper traded if
the user decides to hold an ETF in a paper book.

## What changed

- `src/mb/live/paper.py`: `check_supported` accepts `fixed_weights`. It still refuses the options that failed research
  (M21 `exits.book_stop_frac`, M22 `portfolio.fixed_trend_sessions`).
- A fixed symbol with no bar on the decision day (a halted or late ETF) is sized off its last close before the cut,
  instead of failing. Picks always have a bar because ranking needs one.
- Decisions record target weights when a fixed sleeve is set, as they already did for non-equal weights.
- `configs/paper/momentum_top40_gold.yaml`: DRAFT paper config pinned to `m19_gold20_invvol_b2`'s resolved hash
  (`5f07ff7a…`), linked daily data, start 2026-10-30. No timer or VPS change.

## Tests

`tests/test_m24_paper_gold.py`: the paper book holds the sleeve at 20% beside the picks and its replay matches the
backtest; a missing sleeve bar uses the last close; the draft config loads and is supported. Full suite: 185 passed.

## Needs the user

Holding an ETF in a paper book is a change to the "stocks only" books (`docs/paper.md`). To run it: approve, set
`start` to the next month-end, add a timer beside the others, and pull on the VPS.
