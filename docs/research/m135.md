# M135: paper support for decision offsets (M106 in four tranches; pre-registered 2026-10-23, before any run)

Eighteenth cycle of the autonomous loop. LOOP step 10 work (live preparation), not a candidate: no variant is added to
the trial count and nothing here is adopted or deployed.

## Why

M117 found M106's decision day is noise: whole-period Calmar over offsets 0..19 has mean 1.22 (sd 0.15) before tax,
and month-end (1.500) sits about 2 sd above it. Running M106 in four tranches (offsets 0/5/10/15, a quarter of the
capital each, never rebalanced against each other) gives about the mean without the luck (`blend/m117_m106_tranche`,
1.34 before tax). The tranche idea is Hoffstein, Faber & Braun (2020, "Rebalance timing luck"), tested here in M28,
M54, M62, M68 and M117. The paper book refuses `schedule.decision_offset_sessions`, so it can only run the month-end
draw. Queued in the journal since cycle 8.

Research this cycle (journal) found no new signal idea with evidence that is not already dead: same-calendar-month
seasonality (Heston & Sadka 2008) is absent in emerging markets (Li, Zhang & Zheng, 42 markets); no study tests a
small-cap index trend filter (and the M95-M99 benchmark variants are done); Vijaykumar 2026 (SSRN 7394980, ten
momentum definitions on Indian stocks) is not readable here and ranking changes are exhausted (M127-M129).

## What changes

1. `targets(..., open_end=True)` (and `ranked`, `decision_dates`): the panel's last month is still open, so its last
   known session is the decision day. For complete months nothing changes; at offset 0 nothing changes at all.
2. Paper: `decision_offset_sessions` is no longer refused. A session decides when the trading days left in its month
   after it equal the offset: by the NSE holiday calendar (`calendar.sessions_left_in_month`), and by the data when
   the data already reaches the next month (data wins on a disagreement, with a note, as for month-ends now).
3. Replay: decisions in the last month of the replay window are only kept if the book made one there, and are taken
   from `targets(..., open_end=True)` on the panel up to that day (as month-end replays already treat the last session).
4. Draft (not deployed) strategy configs `m135_m106_offN` (N = 5, 10, 15: M106 with only the offset changed) and
   four draft paper configs `momentum_m106_tranche_offN` (N = 0, 5, 10, 15) at ₹2.5 lakh each, start next month-end.
   Deploying them needs the user's OK (it would sit beside or replace the M106 book).

## Checks (pass = the support is right; there is no return bar)

- Tests: on a synthetic panel an offset-5 paper book decides exactly on the session 5 trading days before each
  month-end, its picks and weights equal the backtest at offset 5, and the replay finds no mismatch; offset-0
  behaviour and every existing paper test unchanged.
- End to end: the four draft books run over Jan..Sep 2026 on the newest daily dataset in a scratch store, each
  replay matches, and each decision's picks equal a research run of the same strategy config.
- `m135_m106_offN` reproduce `m111_ref_offN` / `m120_ref_offN` numbers on the same dataset (same strategy, fewer
  null fields).

Fail: any check above; then the support is not offered to the user.

## Results (2026-10-23): all checks pass; support ready, nothing deployed

- Tests: `tests/test_m135_paper_offset.py` (6). An offset-5 book on a synthetic panel decides exactly on the sessions
  with 5 trading days left in the month, its picks and weights equal the offset-5 backtest, and the replay matches.
  Run one session at a time (as live: the data never reaches the next month on the decision day), the calendar alone
  picks the same days. A replay in the open month after its decision also matches; the old replay would have failed
  there, because it dated that month's backtest decision 5 sessions before the last known session. The month-end book
  is unchanged. One old assertion (`test_m11_momentum`: paper refuses an offset) now checks the opposite. Suite: 332
  passed, 9 skipped.
- Strategy configs: `m135_m106_off5/10/15` (runs 20261022-233110-9d1482ae, 20261022-233135-29b00d4e,
  20261022-233200-aad031d2, `nse_research@2026-10-14`) have trades and equity files byte-identical to `m120_ref_off5/10/15`
  (runs 20261022-195347-6090c9ee, -195237-b251f25d, -195312-1dccf5e8): Calmar 1.080 / 1.273 / 1.409, CAGR 29.0 / 28.5 /
  28.7%.
- End to end (`notebooks/m135_tranche_e2e.py`): the four draft books (`configs/paper/momentum_m106_tranche_offN`) were
  run from 2026-01-01 to 2026-10-22 on the live daily dataset `nse_daily_delivery@2026-10-22`, read only from the paper
  deployment, in a scratch store. Each made 9-10 decisions, each on a session with exactly N trading days left. Every
  replay matched with 0 mismatches; the offset 10 and 15 books had already decided in October, so the open-month replay
  was exercised on real data. Every decision up to 2026-09-28 equals the research targets on `nse_research@2026-10-14`
  (8 of 8 per book; later ones are past the research data). Replay equity gaps were +0.32 / +0.88 / +1.21 / +1.34%
  (offsets 0 / 5 / 10 / 15). This is whole-share rounding at ₹2.5 lakh a tranche (about ₹7,500 a name), under the
  2% alert limit but near it. At this capital, ₹10 lakh a tranche would be safer.

What it gives the user: M106 run as four tranches (M117: about 1.34 Calmar 2010-23 before tax, against the month-end
draw's 1.50, which sits 2 sd above the offsets' mean of 1.22). The expected return is the same as M106's average
decision day, with much less dependence on one day's luck. Not deployed: it would sit beside or replace the running
M106 book, and LOOP step 7 only deploys changes that pass the bar. That is the user's call. To deploy, merge this
branch to `m8` and install one timer per config. Variants for adoption: unchanged (~1,014).
