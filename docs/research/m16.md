# M16: adjust the corporate actions behind unexplained jumps in tradeable names

Pre-registration, written and committed before the new dataset is built or any M16 run (2026-09-30, Claude working
alone overnight at the user's request). Development period 2010-01-04..2023-12-31 only; no `--final`.

## The problem

An unexplained jump (a daily move beyond `unexplained_jump`, 1.5×, that no corporate action explains) is left in the
adjusted prices. The data gate refuses a run that *holds* a name through one, so no pinned run is affected that way.
But a jump from a real corporate action the data missed still distorts *ranking*: after a demerger or bonus without a
factor, the name looks as if it fell 50–95%, and for the next year (the 252-session lookback) its momentum score is
wrong. M15 found four of these through rename links. This checks the rest.

In `nse_research@2026-09-30b`, 41 unexplained jumps from 2009 to 2023 fall on names that pass the universe filter
(price ≥ ₹50, 50-session median turnover ≥ ₹5 crore) on some session within the year after the jump. Each was checked
against the feed and the prices:

- **26 are real corporate actions** the data did not adjust (below). 18 are demergers or schemes of arrangement the feed
  lists without a factor; 6 are bonuses or splits the feed has only as unparsed text; one is a ₹500 special dividend
  (STAR, above `dividend_max_price_fraction`); one is BAJAJFINSV's 2022 split plus bonus, where an earlier
  `purpose_parsed` override carried only the split (0.2) and, since an override replaces every feed row on its date,
  dropped the bonus (true factor 0.1).
- **15 are real price moves** with no corporate action (Satyam 2009, GTL 2011, Core Education 2013, Amtek Auto 2015,
  Infibeam 2018, Jet Airways 2019, Indiabulls Housing 2019 and 2020, Yes Bank 2020, and others). Their prices are right
  and are left alone.

## The fix (override rows; a new dataset version)

`manual` rows in `configs/data/corporate_actions_overrides.csv` (the BAJAJFINSV row is corrected in place; its old
factor is in this file's history). Factors:

- bonus and split: the stated ratio (0.5 for 1:1 and for FV halving; BAJAJFINSV 0.1);
- special dividend: 1 − dividend / prior close (as MAJESCO);
- demerger or scheme: ex-date open / cum-date close (as KPIT and TATACHEM). For TEXINFRA and ADANIENT the ex-date open
  was still at the old price band (ADANIENT opened at exactly 0.9× the cum close, then closed at 0.17×), so the
  ex-date close is used instead; otherwise the matcher would find the factor too far from the observed gap and not
  apply it.

| special dividend | STAR 2013-12-19 |
| demerger / scheme | TEXINFRA 2010-11-01, ADANIENT 2015-06-03, MASTEK 2015-06-12, IDFC 2015-10-01, ABIRLANUVO 2016-01-20, CGPOWER 2016-03-15, OMKARCHEM 2017-06-12, ORIENTPPR 2018-01-11, ARVIND 2018-11-28, IIFL 2019-05-30, TATACOMM 2019-09-17, ABREL 2019-10-11, SUVEN 2020-01-21, PEL 2022-08-30, KAMDHENU 2022-09-06, MIRZAINT 2023-03-29, EDELWEISS 2023-06-02, NIITLTD 2023-06-08 |

A new dataset `nse_research@2026-09-30c` is built from the same data config (`nse_research_linked.yaml`). Expected: 26
fewer unexplained jumps (1,094 → 1,068), adjusted prices changed only for these 26 symbols, all checks pass.

## Runs (question `momentum-m16-jumps`)

The four M15 reference configs (`m15b_off0_{b1,b2}`, `m15b_invvol_off0_{b1,b2}`) are copied with only `dataset`
changed: `m16_{b1,b2,invvol_b1,invvol_b2}`.

This is a data correction, not a strategy idea, so there is no pass bar. Reported: the build's jump count and checks;
each run against its M15 pin (`momentum/m15b_*`), whole period and folds; whether inverse-vol still beats equal weight
on both books (whole period and folds). A change of more than 0.05 Calmar in any window is traced to named trades
before anything is concluded. If inverse-vol no longer beats equal weight on whole-period Calmar on either book, the
paired offsets of M15 are re-run on the new dataset before the recommendation is restated. If the build fails its
checks, that is reported and the M15 pins remain the references.

## Disclosure

- The M15 results are known; the effect of these corrections is not. The list of rows was fixed from the feed and the
  prices alone (no backtest was run on it).
- The eligibility filter uses turnover on or after the jump, which is fine for choosing which data to fix (it is not a
  trading rule). Jumps in names that never became tradeable within a year are not checked.
- The CSV is shared by all data configs. Of the rows, EDELWEISS, NIITLTD, MIRZAINT and HERITGFOOD fall in 2023, inside
  the window that later `nse_daily` builds read (from 2023): those builds would adjust those four names' 2023 history
  too, which is correct. The running paper books are not rebuilt by this work.
- Dataset ~350 MB; the Mac has ~6.6 GB free.
