# M5 research: momentum variants and SEPA + momentum blends

Pre-registration, written before the tagged runs. Development period 2010-01-04..2023-12-31 only; nothing here touches
the locked period (from 2024-01-01). Adoption metric: Calmar (`configs/baselines.yaml`).

## Dataset

All M5 runs use `nse_research@2026-09-29b`. It differs from `nse_research@2026-09-29` only in corporate actions:

- Feed rows are re-keyed by ISIN to the symbol the company traded under at the time (the NSE feed lists actions under
  today's symbol). Matched share events 1340 -> 1367; unexplained jumps 1139 -> 1118 (21 removed, none added).
- Three manual overrides: AEGISCHEM bonus 2010-08-18, KPIT demerger 2019-01-24, NCC rights 2014-09-18. Rights and
  demergers adjust price only, never volume.
- One reviewed real move, `configs/data/verified_price_moves.csv`: IGL 2012-04-10 (regulator tariff order; volume 47.2m
  vs 0.68m average). It is a real price move, not a data error, so the gate no longer refuses trades across it.
- Rows: 8,345,112 in both.

Why: the momentum variants held names across jumps the old dataset could not explain, and the data gate refused them.
SEPA is re-run on the new dataset as `strategies/sepa/configs/v1_port_dev_b.yaml` (same parameters as `v1_port_dev`) so
every comparison uses the same data. `sepa/v1_port_dev` stays pinned and unchanged.

## Question 1: `momentum-variants`

Pin to beat: `momentum/baseline_dev` (`strategies/momentum/configs/baseline_dev.yaml`). It uses the 12-1 baseline's
settings, so its strategy metrics must equal `metrics.baselines.momentum_12_1` exactly; that is checked before pinning.

Variants, each changing one thing from the baseline, plus one with all four. This list is fixed; no other variants.

| Config | Change |
|---|---|
| `stocks_dev` | Drop ETFs and other fund units (ISIN starting `INF`) |
| `regime_dev` | Go to cash at a month-end when NIFTYBEES closes below its 200-session average |
| `voladj_dev` | Rank by 12-1 return divided by the stdev of daily log returns over the same span |
| `buffer_dev` | Keep a held name while it ranks in the top 60 (new buys still fill the top 30) |
| `combined_dev` | All four |

Adoption: beat the pin and both baselines on Calmar, on the whole period and on each of the three folds.

## Question 2: `sepa-momentum-blend`

Pin to beat: `sepa/v1_port_dev_b`. The adoption bar already requires beating the momentum baseline too.

- Blend 1, `strategies/blend/configs/sepa_momentum_dev.yaml`: 50% SEPA (`v1_port_dev_b`), 50% momentum baseline.
- Blend 2: 50% SEPA, 50% the momentum variant with the highest whole-period Calmar in question 1 (the baseline if no
  variant beats it). Written after question 1 runs, following this rule only.

Sleeves start with fixed capital shares and are never rebalanced against each other. No other weights are tried.
